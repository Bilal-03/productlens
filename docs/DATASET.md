# Synthetic Dataset

The generator creates users, sessions, events, subscriptions, and transactions over at least 180 days. The portfolio profile targets 20K users, 120K sessions, 500K–650K events, 12K subscriptions, and 25K transactions while remaining below the Supabase free database ceiling. The current full in-memory profile produces 624,021 events.

The seed is `20260824`; data ends at 2026-08-23 UTC. Relative dates resolve against this metadata instead of wall-clock time, making demo questions reproducible.

The dataset contains no real personal information. Country, channel, device, browser, plan, company size, campaign, customer type, revenue motion, and failure reason are governed dimensions. Lifecycle events (`subscription_started` and `subscription_cancelled`) are emitted for subscription records; payment failures carry a structured `failure_reason` property and are emitted only after a submitted payment attempt.

Run `DATABASE_ADMIN_URL=... backend/.venv/bin/python -m app.data.generate --profile full --load` to load and validate. The loader checks all documented scenario directions from generated rows and fails the load if a full-profile gate is not met. Scenario checks use set-based event flags and a bounded 120-second administration timeout so the full seed remains viable on small Supabase compute tiers. If loading has already committed and only validation needs to be retried, run `make seed-validate`; it does not regenerate or overwrite data. The smoke profile uses the same checks, with D30 acquisition-retention and SMB MRR direction reported as sample-sensitive rather than treated as full-profile acceptance gates. The full profile gates checkout, onboarding, integration/team D30 association, acquisition quality, SMB monthly MRR/revenue plus failed renewals, and lifecycle-event completeness.
