# Evaluation

Evaluation separates deterministic correctness from model variability.

- Unit fixtures validate metrics, periods, funnels, retention, and contribution arithmetic exactly.
- The safety corpus must reject every destructive, injected, multi-statement, system-table, and unbounded query.
- A curated benchmark stores expected intent, metric, dimensions, tables, chart type, and approximate answer for 58 questions spanning every supported P0/P1 category.
- With `--with-database`, governed current-period queries are executed against the configured database and finite numerical results are recorded; this is a smoke correctness check, not a substitute for exact fixture assertions.
- Live provider evaluation is optional and emits timestamped results with the provider/model named.
- README metrics are published only after a real evaluation run.

The P2 proactive suite additionally covers rolling-baseline gates, z-score and percentage thresholds, zero-variance behavior, minimum samples, episode collapsing, governed `payment_failures` semantics, bounded daily-series SQL, bounded-concurrency report execution, cache hits and dataset-version invalidation, partial metric warnings, provider timeout/grounding fallback, typed API responses, Markdown content-disposition, and Product Pulse/report component rendering. PostgreSQL integration fixtures should verify the seeded checkout incident and its `Mobile / Safari / Paid Social` driver; those checks require the migrated local or CI database and are not inferred from offline unit tests.

Phase 39–40 coverage additionally tests deterministic experiment assignments, signup-eligible activation denominators, uplift and relative-uplift arithmetic, normal-approximation intervals, significance and minimum-sample guards, experiment/advanced API contracts, allowlisted advanced dimensions and journey events, observed immature revenue cohorts, UTC daily-activity rollup semantics, dataset-version cache invalidation, partial advanced-query warnings, and desktop/mobile route reachability. The PostgreSQL integration suite executes the seeded onboarding experiment and advanced analytics queries after migrations through `0006_daily_activity`; it remains skipped when no database is available.

Phase 43 coverage additionally tests session ownership, idempotent save behavior, typed saved-analysis projections, bounded list/delete/summary contracts, empty and populated notebook states, deterministic aggregation and evidence/source attribution, Copilot source links, responsive summary rendering, and notebook route reachability. The notebook stores only server-validated history snapshots; it does not accept client-supplied SQL or evidence payloads, and executive-summary generation does not rerun source queries.

The P3 suite additionally tests signed assertion round trips, tamper/expiry/future-issue rejection, explicit role permissions, workspace/subject session isolation, anonymous compatibility, the access-context contract, `401` invalid-token handling, and `403` notebook-write enforcement. Supabase/OIDC coverage adds RSA-signed bearer-token checks for issuer, audience, required expiry, subject, key-id rotation, exact group mapping, RBAC, and tenant context. Connector coverage verifies server-only source resolution, missing mappings, PostgreSQL contract allowlists, read-only transactions, health failures, dataset fingerprints, and tenant/source cache namespaces. SSE coverage verifies authorization, event framing, bounded snapshots, heartbeats, fingerprint updates, `Last-Event-ID`, CORS preflight support, and reconnect semantics. Orchestration coverage verifies the fixed Planner/Analyst/Evidence handoffs, capability restrictions, bounded metadata, and deterministic fallback. Enterprise SSO provisioning, dynamic connector management, and permanent real-time infrastructure remain outside this milestone.

The current offline benchmark is 58/58 (`make benchmark`). It checks planner intent/metric/dimensions, compiler table coverage, and controlled chart inference. `make benchmark` intentionally does not claim a live-provider score; provider evaluations must be timestamped separately with the actual model and measured results. The overview refresh path additionally validates that the 90-day revenue and signup trends use one governed grouped daily query each, preserving the weekly chart contract without serial bucket round trips.

On the clean full-profile local PostgreSQL fixture, uncached acquisition, feature-adoption, retention, and overview calls completed in approximately 442 ms, 1.50 s, 882 ms, and 3.18 s respectively; the cached overview repeated in 3 ms. These are engineering checks on the fixture hardware, not an SLA for Supabase or Vercel.
